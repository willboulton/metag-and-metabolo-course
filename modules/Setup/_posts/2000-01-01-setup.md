## Overview

This section walks through setting up your computational environment for metagenomics and metabolomics analysis. We use:

- **MATAFILER4**: A bioinformatics pipeline for quality control, assembly, binning, taxonomic classification, and functional annotation of metagenomic data
- **Custom metabolomics pipeline**: Preprocessing, normalization, and annotation of mass-spectrometry data as described in the DIME paper
- **R**: For visualisation, statistical analysis, and network inference
- **SpiecEasi**: R package for sparse inverse covariance network analysis of microbiome and metabolomics data
- **vegan**: R package for community ecology and diversity analysis
- **DDT**: A custom R-based tool that automates standard statistical analyses for metagenomics and metabolomics (differential abundance, diversity, ordination)

## System Requirements

Our workflow has three parts: 

1. The metagenome analysis and MAG generation with MATAFILER4
2. Metabolomics preprocesing, using ...
3. Integration of these two datasets, with SpiecEasi

Out of these, 2. and 3. can be done on any modern laptop (though we would recommend using a Linux distribution as your OS). 
However, 1. really needs an HPC system - you'll need at least 1 TB of storage (raw read files, and the GTDB database, are over 500 GB alone), and at least 10 nodes with pretty decent RAM and compute requirements (e.g. 64 GB, 16 cores). 

The output of 1. is a MAG abundance table, and a set of annotated MAGs.

## Part 2: MATAFILER4 Installation

MATAFILER4 is the core pipeline for generating metagenome-assembled genomes (MAGs) and abundance tables.

### What MATAFILER4 Does

MATAFILER4 is an end-to-end Nextflow-based pipeline that wraps a set of established tools into a reproducible workflow:

1. **Quality Control**: Adapter trimming and quality filtering (fastp); host read removal (Bowtie2 against human reference)
2. **Assembly**: Co-assembly or per-sample assembly of reads into contigs (metaSPAdes / MEGAHIT)
3. **Read Mapping**: Maps reads from all samples back to assembled contigs (BWA-MEM2 or Minimap2) to derive per-sample coverage
4. **Binning**: Groups contigs into genomic bins using an ensemble approach (MetaBAT2, MaxBin2, CONCOCT) followed by bin refinement (DAS_Tool)
5. **Quality Assessment**: Evaluates completeness and contamination of bins using CheckM2; generates summary statistics
6. **Dereplication**: Creates a non-redundant set of MAGs across all samples (dRep), with pairwise ANI clustering
7. **Taxonomic Classification**: Classifies MAGs using GTDB-Tk against the GTDB reference tree
8. **Functional Annotation**: Gene prediction (Prodigal) followed by annotation against KEGG (via DIAMOND), COG, and Pfam databases
9. **Abundance Quantification**: Generates a final MAG abundance table (coverage per sample, normalised to TPM or relative abundance)

### Installation

[Detailed MATAFILER4 installation instructions to be added — refer to the tool's GitHub repository and documentation]

MATAFILER4 is built on Nextflow and manages most dependencies via Conda or Docker automatically. The broad steps are:

```bash
# 1. Install Nextflow (requires Java 11+)
curl -s https://get.nextflow.io | bash

# 2. Clone the MATAFILER4 repository
git clone https://github.com/[your-org]/MATAFILER4.git
cd MATAFILER4

# 3. Run with the bundled conda/docker profile
nextflow run main.nf -profile conda --input samplesheet.csv --outdir results/
```

### Configuration

MATAFILER4 requires a samplesheet (CSV) listing your samples and read files:

**samplesheet.csv:**
```
sample,fastq_1,fastq_2
DIME_001,/data/raw/DIME_001_R1.fastq.gz,/data/raw/DIME_001_R2.fastq.gz
DIME_002,/data/raw/DIME_002_R1.fastq.gz,/data/raw/DIME_002_R2.fastq.gz
```

Key parameters (set in `nextflow.config` or via command line):

```
--min_completeness   50     # Minimum MAG completeness (%) to retain
--max_contamination  10     # Maximum MAG contamination (%) to retain
--derep_ani          0.95   # ANI threshold for dereplication
--assembly_tool      metaspades  # or megahit
```

### Running MATAFILER4

```bash
nextflow run main.nf \
  -profile conda \
  --input samplesheet.csv \
  --outdir DIME_results/ \
  --min_completeness 50 \
  --max_contamination 10
```

Expected runtime: Several hours to days depending on sample number and available compute. For the DIME dataset we recommend running on an HPC cluster with the provided SLURM profile.

### Expected Outputs

MATAFILER4 will produce:

1. **MAG files**: Individual .fa (FASTA) files for each genome bin
2. **Abundance table**: .csv with MAG abundance across samples
3. **Taxonomic assignment**: .csv with taxonomy for each MAG
4. **Functional annotation**: Gene predictions and KEGG annotations for each MAG

## Part 3b: DDT — Automated Statistical Analysis

**DDT** is a custom R-based tool developed alongside this course to automate routine statistical analyses that are commonly applied to metagenomics and metabolomics data. Rather than writing the same code repeatedly for each dataset, DDT provides a consistent, documented interface for:

- Alpha diversity calculation and comparison across groups
- Beta diversity (ordination) with statistical testing (PERMANOVA, ANOSIM)
- Differential abundance analysis with multiple testing correction
- Automatic generation of publication-ready figures

### When to Use DDT vs. Manual R Code

This course uses **both**:
- The **Workflow section** shows step-by-step R code so you understand what each analysis is doing
- **DDT** is then used to run the same analyses efficiently on the full dataset and generate final figures

DDT is particularly useful when you want to apply the same suite of analyses to multiple datasets or compare results across studies.

### Installation and Basic Usage

```r
# Install DDT
remotes::install_github("[your-org]/DDT")
library(DDT)

# DDT takes a phyloseq object as input
# See the Workflow section for how to construct this
ddt_results <- run_ddt(
  physeq = your_phyloseq_object,
  group_var = "treatment",        # Column in sample metadata
  output_dir = "results/DDT/"
)
```

## Part 4: Metabolomics Data Processing

The DIME study used **untargeted LC-MS/MS metabolomics** (both positive and negative ionisation mode). The preprocessing pipeline described in the paper is custom and uses a combination of vendor software and in-house scripts. The key steps are summarised here; the full processing protocol is available in the DIME paper's supplementary methods.

### Overview of the Custom Metabolomics Pipeline

The pipeline starts from raw instrument files and produces a normalised feature matrix:

1. **Peak detection and feature alignment**: Identify mass spectral features (defined by m/z and retention time) across samples and align them to a common feature table
2. **Blank and QC filtering**: Remove features that are not reproducibly detected in quality control (pooled QC) samples, or that are present in extraction blanks
3. **Normalisation**: Correct for systematic variation using pooled QC samples (e.g., LOESS-based signal correction); apply sample-level normalisation (e.g., total ion current or dilution factor)
4. **Feature annotation**: Match features to reference databases (HMDB, KEGG, MassBank) using accurate mass and MS/MS fragmentation spectra; annotation confidence is reported as Metabolomics Standards Initiative (MSI) levels 1–4
5. **Polyphenol-specific annotation**: The DIME pipeline includes a curated database of polyphenol metabolites and their microbial biotransformation products, enabling annotation of bioactive-related features that are absent or poorly represented in general-purpose databases

The pipeline is implemented in Python and R. [Full scripts and documentation to be added — refer to the DIME paper supplementary materials and GitHub repository]

### Expected Format

Your final metabolomics data should be:
- **Features table**: .csv with features as rows, samples as columns, intensity values
- **Feature metadata**: .csv with m/z, retention time, compound ID (if annotated), KEGG ID (if available)
- **Sample metadata**: .csv with sample information (treatment, timepoint, donor, etc.)
