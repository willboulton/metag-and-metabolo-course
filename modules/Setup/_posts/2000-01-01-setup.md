## Overview

This section walks through setting up your computational environment for metagenomics and metabolomics analysis. We use:

- **MATAFILER4**: A bioinformatics pipeline for quality control, assembly, binning, taxonomic classification, and functional annotation of metagenomic data
- **Custom metabolomics pipeline**: Preprocessing, normalisation, and annotation of mass-spectrometry data as described in the DIME paper
- **R**: For visualisation, statistical analysis, and network inference
- **SpiecEasi**: R package for sparse inverse covariance network analysis of microbiome and metabolomics data
- **vegan**: R package for community ecology and diversity analysis

---

## System Requirements

Our workflow has three parts: 

1. The metagenome analysis and MAG generation with MATAFILER4
2. Metabolomics preprocesing, using MZMine, and the R packages XCMS and CAMERA
3. Integration of these two datasets, in R, with SpiecEasi

Out of these, 3. can be done on any modern laptop (though we would recommend using a Linux distribution as your OS). 
However, 1. and 2. really need an HPC system - you'll need at least 1 TB of storage (raw read files, and the GTDB database, are over 500 GB alone), and at least 10 nodes with pretty decent RAM and compute requirements (e.g. 64 GB, 16 cores). 

The output of 1. is a MAG abundance table, functional and taxonomic annotations and profiles, and a set of annotated MAGs. 
The output of 2 is similar, absolute concentrations for SCFAs in the targetted metabolomics, and relative abundances of annotated targeted metabolites from the untargeted metabolomics.

## Part 2: MATAFILER4 Installation

MATAFILER4 is the core pipeline for generating metagenome-assembled genomes (MAGs) and abundance tables.

### What MATAFILER4 Does

MATAFILER4 is an end-to-end pipeline that wraps a set of established tools into a reproducible workflow:

1. **Quality Control**: Adapter trimming and quality filtering (SDM); host read removal (hostile)
2. **Assembly**: Co-assembly or per-sample assembly of reads into contigs (metaSPAdes / MEGAHIT)
3. **Read Mapping**: Maps reads from all samples back to assembled contigs (BWA-MEM2, Minimap2 or Strobealign) to derive per-sample coverage
4. **Binning**: Groups contigs into genomic bins using a choice of binner (MetaBAT2, SemiBin2, or SCGBinner) 
5. **Quality Assessment**: Evaluates completeness and contamination of bins using CheckM2; generates summary statistics
6. **Taxonomic Classification**: Classifies MAGs using GTDB-Tk against the GTDB reference tree
7. **Functional Annotation**: Gene prediction (Prodigal) followed by annotation against KEGG (via DIAMOND), COG, and Pfam databases. This is done sample-wide and generates a gene catalogue
8. **Dereplication**: Creates a non-redundant set of MAGs across all samples using a customised method based on shared genes within the gene cataglogue. Other pipelines would often use a tool such as dRep for this step
9. **Abundance Quantification**: Generates a final MAG abundance table (coverage per sample, normalised to RPM)

### Installation

We'll follow the instructions on [the tutorial page](https://github.com/hildebra/MATAFILER4/blob/main/helpers/documentation/install.md):

```bash
# 1. Clone the MATAFILER4 repository
git clone https://github.com/hildebra/MATAFILER4.git
cd MATAFILER4

# 2. Run with the bundled conda/docker profile
source helpers/install/installer.sh

# 3. Check your installation
micromamba run -n MF4 ./MATAF4.pl -checkInstall

# 3. Configure paths and databases
# edit your config.txt file using an editor e.g. notepad, nano, vim
# this file is very strictly tab separated (not any other whitespace)
# You'll need to set (at a minimum): MFLRDir, BINDir, DBDir, nodeTmpDir, globalTmpDir, shortQueue, mediumQueue, longQueue
# Some of these parameters, such as the appropriate scratch space per node, you might need to find out from your system administrator

# 4. Install GTDB database - here version 226 (but could be updated)
source helpers/install/get_gtdb.py all -v 226 -t /path/to/download/to -d /path/to/extract/to --tk split

# 5. Run the example to test that everything works
cd $MF4DIR/examples
bash 0.getExmplData.sh
bash 1.runMF4_illumina.mfc
```

### Configuration

MATAFILER4 requires a tab separated file listing your samples and read files (and optionally, metadata), called a mapping file. 
There are some examples in `$MF4DIR/examples/maps`, for DIME, 

**samplesheet.map:**
```bash
#SmplID SmplPrefix  SeqTech
#RunID  dime_metagenomics_v1
#OutPath  /my/scratch/dime/metag_results
#DirPath  /my/scratch/dime/fastqs
P01.V1  ERR10125296  hiseq
P01.V2  ERR10125297  hiseq
P02.V2  ERR10125302  hiseq
# etc.
# The sample id stands for P(articipant)<Participant_ID>.V(isit)<Visit_Number>. 
# This is the minimum amount of metadata we'll need to link the metagenomic sample 
# with metabolomics and other participant metadata e.g. age, sex. 
```

You'll then need a script with all the options MATAFILER uses provided. 
This is just a bash script (to be submitted to the SLURM cluster from a submission node), 
but we've given it the extension mfc for MATAFILER control. 

**dime_analysis.mfc**

```bash
#!/usr/bin/env bash
#SBATCH -N 1
#SBATCH --cpus-per-task=1
#SBATCH -o %J.out
#SBATCH -e %J.err
#SBATCH --mem="16G"
#SBATCH --export=ALL
#SBATCH -p "ei-compute" # Your HPC queue would be different
#SBATCH --time=248:00:00 # Your upper time limit could also be different
#SBATCH -J MATAFILER_DIME_RUN_V1

set -e;
ulimit -c 0;

eval "$(micromamba shell hook --shell bash)"

micromamba activate MF4

MAP=/path/to/your/dime/samplesheet.map

MF4_PARAMS=(
  # Run with max 800 concurrent jobs, remove locks
  -submit 1
  -map $MAP
  -rmSmplLocks 1
   -maxConcurrentJobs 800
  # Detected PE reads - let assembler merge them
  -inputFQregex1 '(.*_1\.fastq\.gz)|(.*[_\.]1\.f[^\.]*q\.gz)$'
  -inputFQregex2 '(.*_2\.fastq\.gz)|(.*[_\.]2\.f[^\.]*q\.gz)$'
  -mergeReads 0
  # These are the default SDM options for short reads - you can change them and see how the results vary
  -customSDMopt "$MF4DIR/data/sdm_opt_inifilter.txt"
  # Use Hostile to filter out human contamination
  -filterHostRds 3
  -hostileIndex human-t2t-hla
  # MEGAHIT assembly, 12 cores, 24GB
  -assembleMG 2
  -assemblCores 12
  -assemblyKmers "25,43,67,87,111,127"
  -assemblMemory  24
  # SemiBin2 with CheckM2
  -Binner 3
  -redoEmptyBins 1
  -checkM2 1
  -forceWriteStats 1
  # Map reads to assembly w/ Strobealign, 24GB
  -mapReadsOntoAssembly 1
  -mapper 5
  -saveReadsNotMap2Assembly 0
  -mappingMem 24
  -mapSaveCRAM 1
  # We won't do SNP profiling here, turn this off
  -profileMetaphlan 0
  -getAssemblConsSNP 0
  -SNPsaveVCF 0
  -SNPmem 64
  -from 0 -to 3 # Just test the first 3 samples on the first run, if all works well, switch -to to 999
)

perl $MF4DIR/MATAF4.pl "${MF4_PARAMS[@]}"
```

## Part 3: Metabolomics Data Processing

The DIME study used **untargeted LC-MS/MS metabolomics** (both positive and negative ionisation mode). The preprocessing pipeline described in the paper is custom and uses a combination of vendor software and in-house scripts. The key steps are summarised here; the full processing protocol is available in the DIME paper's methods section.

### Overview of the Custom Metabolomics Pipeline

The pipeline starts from raw instrument files and produces a normalised feature matrix:

1. **Convert files to a standard open format using [ProteoWizard](https://proteowizard.sourceforge.io/index.html)**: this step takes the RAW format files (the format used by Thermo Fisher) and converts them to mzML format, which is an open standard, compatible with a larger number of analysis tools. 
1. **Peak detection and feature alignment**: Identify mass spectral features (defined by m/z and retention time) across samples and align them to a common feature table. This is done in R using the [XMCS](https://bioconductor.org/packages/release/bioc/html/xcms.html) package and CentWave algorithm. 
2. **Blank and QC filtering**: Remove features that are not reproducibly detected in quality control (pooled QC) samples, or that are present in extraction blanks
3. **Normalisation**: Correct for systematic variation using pooled QC samples (e.g., LOESS-based signal correction); apply sample-level normalisation (e.g., total ion current or dilution factor)
4. **Feature annotation**: Match features to reference databases (HMDB, KEGG, MassBank) using accurate mass and MS/MS fragmentation spectra; annotation confidence is reported as Metabolomics Standards Initiative (MSI) levels 1–4. The R package [CAMERA](https://www.bioconductor.org/packages/release/bioc/html/CAMERA.html) does this annotation automatically, but will still leave a relatively large number of metabolites unannotated. 
5. **Polyphenol-specific annotation**: The DIME analysis included a curated database of polyphenol metabolites and their microbial biotransformation products, enabling annotation of bioactive-related features that are absent or poorly represented in general-purpose databases

## Troubleshooting

### Common Installation Issues

**Issue: Missing Perl5Lib**
- Solution: Perl uses a path called "@INC" which might need setting to work properly. Run `perl -e 'print join(":",@INC), "\n";` to see what's on this include path, and if necessary, change it. 

**Issue: Missing Micromamba**
- Solution: Check your .bashrc file, you'll want to make sure that your micromamba is set up there. Alongside that, you'll need at least a PERL5LIB path, and an MF4DIR (which should be set automatically by MATAFILER during the installation, but good to check). 

**Issue: Missing dependencies**
- Solution: These might be in a different environment, run `micromamba env list` to  show you all the installed environments (anything starting with MF4 is MATAFILER related). 

**Issue: Missing databases and other binaries**
- Solution: Apart from GTDB, the smaller databases come with MATAFILER in a `$MF4DIR/data/` subfolder, and some other binaries are in the `$MF4DIR/bin` directory. 

### Getting Help

- Check the tool-specific documentation
- Remember, the config files are tab separated, no other extra whitespace should be there, except on lines with a `#` comment. 
- Review error messages carefully (often indicate missing files or parameters)
- Post issues on relevant GitHub repositories
- Talk to your system administrator about how SLURM is configured, how scratch space is configured, and which queues you should submit jobs to (and time limits for these).
