# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Jekyll static site built on P2PU's [Course-in-a-Box](https://course-in-a-box.p2pu.org) template. It hosts an online course on integrated **metagenomics and metabolomics analysis** (reanalysing the DIME dataset). The site is deployed via GitHub Pages and served directly from the `gh-pages` branch (which is also the default/working branch) — pushing to `gh-pages` publishes.

Almost all substantive work here is **editing course content (Markdown)**, not code. The template layer (layouts, includes, SCSS) is inherited from Course-in-a-Box and rarely changes.

## Running locally

Preview with live reload at http://localhost:4000 :

```bash
docker compose up          # ruby:3.3 + `bundle install` + `jekyll serve --watch`
```

Gems are cached in `.bundler/` (bind-mounted). There is no test/lint/build step beyond Jekyll's own build — verify changes by loading the site in the browser. GitHub Pages rebuilds on push using the `github-pages` gem (see `Gemfile`).

## Content architecture

Course content lives in `modules/`. The structure drives navigation automatically:

- Each **module** is a top-level folder under `modules/` (e.g. `Analysis/`, `Theory/`).
- Each module contains a `_posts/` folder; each **submodule/section** is a Markdown file named `YYYY-MM-DD-name.md`.
- **The date prefix determines section order within a module** (`2000-01-01-...`, `2000-01-02-...`). It is a sorting device only — the dates are not real.
- **Module order across the site is set explicitly** in `_data/course.yml` (`modules:` array). A folder that exists but is not listed there won't appear in navigation.
- `modules/` files get `layout: course_page` automatically (`_config.yml` `defaults`). Post files need only a `title:` in front matter.

Prev/next navigation, the module list, and the sidebar are generated by Liquid includes in `_includes/` (`next_in_module.html`, `navigation.html`, `side_toolbar.html`) from the folder/date structure and `course.yml` — you do not hand-maintain links between pages.

Content images referenced by the course go in `img/` (e.g. `img/analysis/`). The `img/` files named `example-*`, `jumbotron-*`, `dime_logo*`, `course-template.png` etc. belong to the template/branding, not course content.

## Gotchas

- **`baseurl` is not set in `_config.yml`, so `site.baseurl` is empty.** Template-generated links use `{{ site.baseurl }}/...` and resolve as root-relative, but hand-written links inside course Markdown hardcode the repo-name prefix `/metag-and-metabolo-course/...` (the GitHub Pages project path). When adding internal links in content, match the existing hardcoded `/metag-and-metabolo-course/modules/<module>/<section>/` pattern used in `index.md`.
- The landing page is `index.md` (`layout: index`), separate from the module content.
- Course metadata (title/description shown on the site) lives in `_data/course.yml`, not `_config.yml`.
- Site theme colour and logo are configured in `_config.yml` (`jumbotron_color`, `jumbotron_icon`); component styles are in `_sass/` (P2PU theme + Bootstrap) and `css/`.

## Bioschemas / structured metadata

Every page emits [Bioschemas TrainingMaterial](https://bioschemas.org/profiles/TrainingMaterial/1.0-RELEASE) JSON-LD (`@type: LearningResource`):

- `_data/bioschemas.yml` — the course-level record, emitted verbatim on the landing page via `jsonify` (keep it shaped as a valid schema.org object, including the quoted `"@context"`/`"@type"` keys).
- `_includes/bioschemas.html` — included in `_layouts/base.html`'s `<head>`; branches on page type and builds a per-page `LearningResource` (`isPartOf` the course) from post front matter, with fallbacks to the course-level data. Absolute page URLs are built as `course.url + page.url` (the empty `baseurl` means `page.url` lacks the repo prefix).
- Per-page front matter fields (all optional): `description`, `keywords`, `teaches`, `competencyRequired`, `learningResourceType`, `educationalLevel`.

Recommended (non-blocking) enrichments are tracked in **[TODO.md](TODO.md)**, which also documents how to re-validate the JSON-LD after changes.
